## Broken providers and the fixes they need

None of these is a small configuration or code change, so this pass changes no production code.

- **Gemini Chat.** The fix is in progress in the `telly-live-fix` lane (firstmate decision `gemini-bridge`, option c): when no bridge is configured, the server answers with Gemini and no family tools. It then needs a merge and a deploy.
- **River.** Production has no reachable cue endpoint. `QWEN_BASE_URL`, `QWEN_DEPLOYMENT`, and `QWEN_CHECKPOINT` are not set, and `RIVER_API_KEY` is in the store but not in `TELLY_PULL_KEYS`. On 2026-10-04, River refused a dedicated deployment for `Qwen/Qwen3.5-9B` (`unsupported_topology`). `serve.py` listens only on 127.0.0.1, so the container cannot reach it. Two fixes are possible: River approves a deployment specification, or `serve.py` runs behind an HTTPS endpoint that the container can reach. Then set the four values. Also, no web screen calls `POST …/cues` yet.
- **Photon.** The pull Worker serves `SPECTRUM_PROJECT_SECRET`, but `TELLY_IMESSAGE_SENDERS` is not in the store. If the pull list gets the secret without the sender list, the server stops at startup ("Set all of … or none"), so a partial fix takes production down. The full fix has four steps. Add `TELLY_IMESSAGE_SENDERS`, with the captain's address mapped to family 3, to the store or as a Worker secret. Pass `SPECTRUM_PROJECT_ID` (public) in `settings.env`, the `worker.js` `passed` list, and the `deploy.sh` vars. Add the two private keys to `TELLY_PULL_KEYS`. Then deploy. A further risk [INFERENCE]: the container starts only on an HTTP request, so the iMessage agent may stop when the container sleeps.
- **Resend.** Merge and deploy PR #201. In Resend, let the check finish, or click **Restart** on the domain page, so that `rsend` becomes verified. `RESEND_API_KEY` is in the store already.
- **FinchNode records.** No code defect. One person must complete FinchNode Connect once: choose **MyChart (synthetic test patient)**, sign in with the Epic sandbox test patient, and approve sharing. This pass did not do that step, because the browser rules forbid typing a password.
