WHOOP capabilities

Every field NOOP collects from a WHOOP 5.0 / MG strap, where it lives in NOOP's on-device SQLite database, and what kind of value it holds. Values are placeholders: {int} and {float} give the type, followed by the unit. Rows marked "not populated" exist in the schema but had no data on our strap. Real sample rows for every table are in data/<table>.json.

Every second, delivered on sync (every ~15 min)

The strap records these once per second and stores them. NOOP pulls them every 15 min while connected, or as soon as 90 s after an event. On low battery or "Low refresh" it slows to every 45–60 min. None of these can be streamed live. Faster options: "Sync now" skips the limits. The strap's own high-frequency sync mode asks for a sync every 61 s or more for up to 8 hours, but NOOP deliberately stopped using it. Back-to-back syncs from a custom app might get the delay down to seconds, but that's untested. The strap stores history in 4 KB flash pages, so the newest seconds may not be readable until a page is written.

Fall detection

QuestionAnswer
Fastest motion dataThe live 100 Hz accelerometer + gyroscope stream (commands 81 then 106 above). It arrives in 1-second buffers, so expect roughly 1–2 s from a fall to your code. No end-to-end latency has been measured.
RangeAccelerometer 1/4096 g per count, about ±8 g (worked out from the scale, not stated). Gyroscope ±2000 °/s.
Can the 1 Hz gravity data work?No. It only arrives on sync, 90 s to 15 min late.
Built-in fall detection on the strap?Not that anyone has found. The accelerometer-saturated event (42) might fire on a hard impact, but it's untested on 5.0 / MG.
CatchesThe phone must stay connected. NOOP only turns the stream on during a user-started capture session. The battery cost of streaming continuously is unknown.
Typical recipe to tuneFree fall (total acceleration below ~0.3 g for ~0.3 s), then impact (above ~2.5–3 g), then stillness for ~10 s. Confirm with live heart rate, then buzz and alert. Thresholds are common starting points and need tuning on real data.

Vibration motor

QuestionAnswer
ChipTexas Instruments DRV2625 haptic driver
How to buzzCommand 19 (0x13) with a 12-byte body: [01] [8 effect bytes] [loop control, 2 bytes] [repeat]. NOOP sends [01, 47, 152, 0, 0, 0, 0, 0, 0, 00 00, N−1] for N pulses.
Beat patternsYes. Up to 8 effects per command and a repeat of 0–7, so 1–8 pulses. Longer rhythms come from timed separate commands; NOOP's time-telling buzz does this (long = 2 pulses, short = 1).
StrengthNo confirmed control. Only effect IDs 47 and 152 have been tried; each effect byte can be up to 251. Unverified guess from the DRV2625 layout: each effect ID is a different stored waveform, so other IDs may feel stronger or softer, and bytes of 128 and up may be pauses of (value − 128) × 10 ms, which would make 152 a 240 ms gap. That needs testing on the strap. Alarms have a staged "crescendo" ramp flag that NOOP doesn't use.
DelayDouble tap to buzz usually takes under 1 s, or 1–2.8 s when a history sync is already running.
StopCommand 122 [01] on 5.0 / MG. NOOP sends [00], which does nothing on this strap.
Known bugNOOP's "Buzz strap" button also sends RUN_ALARM, which clears stored alarm slot 1, so it can delete a scheduled wake alarm.
